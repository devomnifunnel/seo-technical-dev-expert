# Writing Style Rules

These rules apply to ALL prose output: deliverables, comments, emails, audit findings, recommendations, and Asana updates.

---

## Core Style (non negotiable)

- Never use hyphens or dashes (including em dashes and en dashes) in any written output ever.
- Never use semicolons to join clauses. Use periods instead.
- Vary sentence length. Mix short punchy sentences with longer explanatory ones.
- Use contractions naturally (it's, don't, won't, can't). Formal language sounds robotic.
- Avoid list addiction. When 3+ consecutive bullet points all follow the same structure, rewrite as prose or mix formats.

## Banned Words and Phrases

Replace these AI tells with natural alternatives:

- "Additionally," "Furthermore," "Moreover," "It's worth noting" -> just start the next sentence
- "In order to" -> "To"
- "It should be noted that" -> state the thing directly
- "It's important to" / "It's crucial to" -> just say what to do
- "leverage" -> "use" | "utilize" -> "use" | "facilitate" -> "help" or "enable"
- "landscape" / "tapestry" / "interplay" / "synergy" / "holistic" -> say what you actually mean
- "pivotal" / "testament" / "marks a shift" / "underscores" -> state facts without inflating significance
- "vibrant" / "breathtaking" / "stunning" / "nestled" / "robust" -> use neutral descriptive language
- "serves as" / "stands as" / "boasts" / "features" -> use "is," "are," "has," "have"

## Structural Tics to Avoid

- **Superficial analysis with present participles**: Don't tack on "highlighting X" or "reflecting Y" at the end of sentences for fake depth. Say what you mean directly.
- **Negative parallelisms**: Don't write "Not only X, but also Y" or "It's not just X, it's Y." State both things directly.
- **Rule of three overuse**: Don't force ideas into groups of three for false comprehensiveness. Use natural groupings.
- **Synonym cycling**: Don't cycle through synonyms for the same concept within a paragraph (e.g., "the tool," "the solution," "the platform," "the system"). Pick a term and stick with it.
- **False ranges**: Don't write "From X to Y" when the endpoints lack meaningful connection. List things directly.
- **Generic positive conclusions**: Don't end sections with vague upbeat statements about "exciting possibilities" or "bright futures." End with specific facts, next steps, or concrete observations.
- **Excessive hedging**: Don't stack qualifiers ("could potentially possibly be argued that might"). Use a single confident qualifier: "may," "can," or "might."
- **Vague attributions**: Don't write "Experts argue" or "Industry reports suggest" without naming sources. If you don't have a specific source, don't pretend you do.
